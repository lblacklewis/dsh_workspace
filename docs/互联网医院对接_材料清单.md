# 互联网医院对接 — 需要对方提供的材料清单

> 用途：发给互联网医院 IT / 商务对接人
> 编写日期：2026-10-30
> 我方角色：零售药房线上商城（**处方药销售方**，需凭有效处方售药）
> 对方角色：互联网医院（**开方方**，提供在线问诊 + 处方签发）

---

## 〇、先说清楚：三种对接形态，请对方明确属于哪一种

我方系统已按可插拔方式设计，三种都能接，但**需要什么材料完全不同**，
所以这是第一个必须问清的问题：

| 形态 | 交互方式 | 我方要做的 | 对方要提供的 |
|---|---|---|---|
| **A. 跳转式** | 我方发起问诊 → 返回一个 URL → 用户跳去对方平台问诊开方 → 对方回跳带处方号 | 拼跳转 URL + 处理回跳参数 | 跳转 URL 规则、回跳地址参数约定、签名方式 |
| **B. API 式** | 全程接口交互，问诊和开方都在后台完成 | 调问诊接口 + 轮询/回调取处方 | 完整问诊/处方 API |
| **C. 只读式** | 处方由对方主动推给我方，我方只接收 | 接收并处理回调 | 回调推送协议 + 查询接口 |

> 我方倾向 **B 或 A+B 混合**（用户体验最好），但请对方给建议。

| # | 要什么 | 为什么需要 |
|---|---|---|

| 9 | **计费方式与单价**：按次问诊 / 按张处方 / 按药品金额比例 | 成本核算，直接影响定价 |
| 10 | **结算周期与发票**（月结/预付、普票/专票、税率） | 财务 |
| 11 | **是否有最低消费/保底量** | 影响早期成本 |
| 12 | **责任划分条款**：处方差错由谁担责 | **这条务必写进合同**——药房卖错药，监管先找药房 |
| 13 | 对接联系人：**技术**（含紧急值班电话）+ **商务** | 出事要能立刻找到人 |

> 1. 对方给的图片 URL 是**长期有效**还是**会过期**？
> 2. 是**直接可下载**还是需要**带签名/鉴权**（若需鉴权，请给获取方式）？

## 三、合规相关（P2，但**必须在合同里写清**）

> ⚠️ 本节依据《**处方药网络零售合规指南**》（药监综药管函〔2026〕282号，2026-05-22 实施，
> 现行有效，[原文](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=106008)）。
> 其中**第 19–24 条直接规定了我方与互联网医院的协作方式**，不是可选项。

### 3.1 法规对我方的硬性要求（决定要问对方什么）

| 法规条款 | 内容 | 对合作的要求 |
|---|---|---|
| **第十九条** | 网络销售处方药**必须凭处方**，处方来源须**真实、可靠**，并**实行实名制** | 必须能核验**处方来源真实性**；需取得**患者实名信息**用于比对 |
| **第二十条** | 销售前必须由执业药师**逐项检查处方要素**，确保合法性和用药适宜性 | 对方需提供**完整处方要素**（诊断/医师/药品明细/有效期），缺项无法审 |
| **第二十二条** | ⚠️ 处方审核**必须由本企业执业药师开展**，**不得由其他岗位人员或者人工智能代为实施** | **对方不能替我审方**；我方必须保留并执行最终审方权 |
| **第二十一条** | 通过审核前**不得提供购买服务**；需**避免处方重复使用**；处方/复印件**存档备查**；建议电子签章 | 需拿到**处方原件**用于存档；需处方**唯一性标识**防重复使用 |
| **第二十四条** | 四类情形**应当拒绝调配销售**：①伪造虚假处方 ②已被篡改或**已标记使用**的处方 ③严重不合理用药/用药错误 ④含**禁止网络销售药品**的处方 | 对方需提供**处方状态**（是否已作废/已使用/已篡改），否则我方无法判断 |
| **第十五条** | 销售前须**充分告知用药风险并经消费者确认知情** | 我方前台已有风险提示，需确认与对方问诊告知不重复冲突 |
| **第十二条(三)(四)** | ⚠️ 首页/店铺主页**不得展示处方药包装标签**；**处方审核通过前不得展示说明书，页面不得含功能主治、适应症、用法用量** | 影响我方 H5 商品卡展示（第 20 轮加的"处方药"角标方向是对的） |
| **第二十七条** | 销售凭证须显示**药品追溯码**；最小销售单元销售记录清晰留存 | 需确认我方商品是否已有追溯码数据 |
| **第三十一条** | 妥善保存**购药处方、在线药学服务记录**；线上销售记录须标注**网络载体名称** | 处方留存要求（不再自己猜年限，按 GSP 规定的期限执行） |
| **第十八条** | 处方用药对象为**未成年人**时须告知需监护人同意，必要时拦截 | 需对方在处方里给出**患者年龄/出生日期** |
| **第二十四条(四)** | 含禁止网络销售药品的处方应拒绝 | 需明确排除清单（麻醉/精神/毒性/兴奋剂等） |

### 3.2 因此必须向对方确认的事

| # | 要确认的事 | 我方立场 |
|---|---|---|
| 1 | 对方的**处方审核流程**：是否有执业药师审方？几个药师？ | 对方审方**不能替代**我方审方（第二十二条） |
| 2 | **我方保留最终审方权**，对方处方仅作为"处方来源" | 必须写进合同——我方是售药责任主体 |
| 3 | 处方**能否被篡改/作废**，作废或已使用时如何通知我方 | ⚠️ 必须有回调，否则我方会拿作废处方售药（第二十四条） |
| 4 | 处方是否带**唯一性标识 / 电子签章**，便于防重复使用 | 第二十一条 |
| 5 | 对方能否提供患者**年龄或出生日期** | 第十八条（未成年人拦截） |
| 6 | 对方的**禁止网络销售药品清单**是什么 | 第二十四条第(四)项 |
| 7 | 处方**原件可下载性**（见 2.3 节） | 第二十一条存档备查 |
| 8 | **数据传输加密**要求 | 拒绝明文传输身份证号 |
| 9 | 双方的**数据安全责任边界** | 写进合同 |
| 10 | ⚠️ 我方《药品经营许可证》经营范围是否覆盖拟售处方药 | 需我方自查，也请对方确认开方范围不超我方经营范围（第二十四条研判项） |

### 3.3 我方自身还需落实的合规项（提醒，与对方无关）

- 首页/店铺主页**不得展示处方药包装标签**；审核通过前不展示说明书
- 每个处方药页展示「处方药须凭处方在药师指导下购买和使用」风险警示
- 不得买赠处方药、不得以组合套餐形式销售处方药
- 执业药师配备数量与审方量匹配，**日均审方量控制在合理范围**（第二十三条）
- 向药监部门**报告**网站名称/APP名称/IP/域名/许可证信息，变更 10 个工作日内报告（第六条）
- 主页面显著位置**持续公示**药品经营许可证 + 执业药师资格信息

### 处方药标识问题（第 22 轮排查发现，必须修）

合规指南第十二条要求「在每个药品销售页面上使用处方药或者非处方药的专用标识进行显著区分」。

| 层 | 现状 |
|---|---|
| 数据库 | ✅ `eb_store_product.is_rx` 字段**存在**且已建索引（`MUL`），是权威标识 |
| 后端接口 | ❌ 商品详情 / 商品列表接口**都没有返回 `isRx`**（实测确认） |
| H5 展示 | ⚠️ 我在 `docs/h5-inject.js` 里用**硬编码 + 商品名匹配**兜底：`var RX=[159,102]` + `NAME_HINT` |

1. 后端：商品详情/列表接口把 `isRx` 返回出去
