## 🔧 重建步骤（服务器全清后）

### 1. 恢复 MySQL 配置

```bash
cat > /etc/mysql/conf.d/crmeb.cnf << 'EOF'
[mysqld]
character-set-server=utf8mb4
collation-server=utf8mb4_unicode_ci
innodb_buffer_pool_size=128M
innodb_log_buffer_size=8M
max_connections=50
performance_schema=OFF
skip-log-bin
default-authentication-plugin=mysql_native_password
EOF
systemctl start mysql redis-server
```

> ⚠️ `default-authentication-plugin=mysql_native_password` 必须保留，否则老版本
> MySQL Connector/J 无法连接。

**Redis 密码必须写进配置文件**（只 `CONFIG SET` 设的话，一重启就丢）：

```bash
grep -q "^requirepass" /etc/redis/redis.conf \
  && sed -i 's/^requirepass .*/requirepass redis_dMtNMj/' /etc/redis/redis.conf \
  || echo "requirepass redis_dMtNMj" >> /etc/redis/redis.conf
systemctl restart redis-server

# 验证：不带密码应被拒，带密码应 PONG
redis-cli PING                                    # NOAUTH Authentication required.
redis-cli -a redis_dMtNMj --no-auth-warning PING  # PONG
```

> 🔴 **踩坑记录（2026-10-27 后台登录不了的真凶）**
> Redis 无密码、而后端 `application-dev.yml` 配了 `password: redis_dMtNMj` 时，
> Jedis 抛 `ERR AUTH <password> called without any password configured`，
> 连接池拿不到连接 → **token 无法读写 → 所有鉴权接口返回 401**。
>
> 迷惑点：HTTP 状态码是 **200**，只有 body 是 `{"code":401,...}`。
> 排查技巧：看 nginx access log 的响应体大小，**49 字节** 就是这个 401 响应
> （`{"code":401,"message":"未登录，请登录！"}` 恰好 49 字节）。
> 患者症状：登录按钮点完变灰、页面反复弹「无效的会话」「Verification failed」。

```bash

mysql -uroot -e "CREATE USER IF NOT EXISTS 'java_dev'@'localhost' IDENTIFIED WITH mysql_native_password BY 'NPKntRXcCrx2AZ3i';"
mysql -uroot -e "CREATE USER IF NOT EXISTS 'java_dev'@'%' IDENTIFIED WITH mysql_native_password BY 'NPKntRXcCrx2AZ3i';"

```

### 4. Maven 构建后端

```bash
# 阿里云镜像（必须，Central 慢）
mkdir -p /root/.m2 && cat > /root/.m2/settings.xml << 'EOF'
<settings xmlns="http://maven.apache.org/SETTINGS/1.0.0">
  <mirrors><mirror>
    <id>aliyunmaven</id><mirrorOf>*</mirrorOf>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror></mirrors>
</settings>
EOF

cd /opt/storapp/crmeb
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
export MAVEN_OPTS="-Xmx512m"
mvn clean package -DskipTests -B     # 约 1.5 分钟
```

### 5. 启动后端 + Nginx

```bash
bash /opt/storapp/start.sh
systemctl start nginx
```

> `start.sh` 用 `--crmeb.imagePath=/opt/storapp/images/` 覆盖源码里的默认路径，
> 无需改 yml 重新打包。

## ⚠️ 踩过的坑

| 问题 | 原因 | 解决 |
|------|------|------|
| `vue-cli-service` 找不到 | app 只有 mp-html，无 CLI 工具链 | 补 `@vue/cli-service`/`vue`/`babel.config.js`/`postcss.config.js` |
| `Cannot find module @dcloudio/uni-cli-i18n` | CLI 依赖未装全 | 装 `uni-cli-i18n`/`uni-i18n`/`uni-template-compiler`/`webpack-uni-pages-loader` 等，**版本必须统一为 `2.0.2-5020420260813001`** |
| 混用 HBuilderX 内置包报 `reading 'use'` | HBuilderX 内置是旧 alpha 版 | 不要混用，全部走 npm 同版本 |
| `pkill -f 'Crmeb-admin.jar'` 自杀 | `-f` 匹配到承载命令的 shell 自身 | 用精确 PID `kill <pid>` |
| MySQL 8 严格模式导库失败 | 严格 sql_mode | `--init-command="SET SESSION sql_mode='NO_ENGINE_SUBSTITUTION'"` |
| 分类 SQL 报 `Unknown column 'cate_name'` | 实际列名是 `name`，且无 `is_del` | 已修正 `docs/药品分类数据.sql` |
| 前端登录 404 | 路径少了 `api/front` 前缀 | Front 控制器是 `@RequestMapping("api/front")`，完整路径 `/front-api/api/front/login` |
| 前端登录字段错 | DTO 用 `account` 不是 `phone` | 传 `{"account":"...","password":"..."}` |
| PS 脚本中文乱码 | PS 5.1 读 UTF-8 无 BOM 当 ANSI | `.ps1` 必须存为 **UTF-8 with BOM** |
| H5 页面标题是 `Vue App` | `manifest.json` h5.title 为空 | 设为 `StorApp 健康药房`（已改源码并补丁已部署文件） |
| **后台登录不了 / 一直弹「无效的会话」** | **Redis 无密码，后端配了密码** | 把 `requirepass redis_dMtNMj` 写进 `/etc/redis/redis.conf` 并重启（见「重建步骤 1」） |
