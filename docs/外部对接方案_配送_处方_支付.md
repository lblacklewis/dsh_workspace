## 一、即时配送（美团/饿了么骑手）

### 1.1 三条可选路径

| 路径 | 接入方式 | 优势 | 劣势 | 建议 |
|------|---------|------|------|------|
| **A. 微信「物流助手-即时配送」** | 小程序原生能力，微信聚合多家运力 | 一次接入美团/蜂鸟/达达/顺丰同城；用户在小程序内直接看骑手位置；无需逐个签约 | 仅小程序可用（H5 不行）；需先开通微信支付 | ⭐ **首选** |
| **B. 快递100 同城急送** | [api.kuaidi100.com](https://api.kuaidi100.com/document/tong-cheng-ji-jian-chan-pin-jie-shao) 聚合 API | 接入最快（1 周内）；H5 + 小程序都能用；一次对接多家运力 | 多一层服务商，抽成；时效数据略滞后 | ⭐ **备选/兜底** |
| **C. 直连运力商** | [美团配送开放平台](https://developer.meituan.com/docs/biz/biz-peisong-biz-apply) / [蜂鸟即配](https://open.ele.me/documents/openApi/771) | 费率最低；数据最全 | 需分别商务签约、门店入驻；每家一套签名和回调，开发量 ×N | 单量起来后再考虑 |

**建议**：先做 **A**，用 **B** 兜底 H5 场景。架构上做成可插拔，将来切 C 不用改业务代码。

### 1.2 业务流程

```
用户下单（选择"同城配送"）
   ↓
服务端询价（quote）→ 返回运费、预计送达时间
   ↓
用户支付成功
   ↓
服务端发单（create）→ 拿到运力商订单号 + 骑手信息
   ↓
运力商回调（callback）→ 骑手已接单 / 已取货 / 配送中 / 已送达
   ↓
订单状态同步 + 给用户推送消息
```

### 1.3 核心接口

| 动作 | 我方接口 | 说明 |
|------|---------|------|
| 询价 | `POST /api/front/delivery/quote` | 传收货地址 + 门店，返回运费和时效 |
| 发单 | `POST /api/admin/delivery/dispatch` | 商家手动发单（也可支付后自动） |
| 查询 | `GET /api/front/delivery/status/{orderNo}` | 订单详情页轮询 |
| 取消 | `POST /api/admin/delivery/cancel` | 仅未接单可取消 |
| 回调 | `POST /api/front/delivery/callback/{provider}` | 运力商 → 我方，需验签 |

## 二、互联网处方

### 2.1 现状

**CRMEB 完全没有任何处方/问诊代码**，属于全新模块。

### 2.2 合规红线（必须遵守）

- **先方后药**：处方药必须凭处方销售，不能先付款后补方
- **药师审核**：处方必须经执业药师审核通过才能售药
- **处方留存**：处方及审核记录需保存 **≥2 年**（部分地区 5 年）
- **禁止展示**：处方药不得对公众做广告、不得直接展示给未登录用户
- **实名**：购买处方药需实名（姓名 + 身份证）

### 2.3 业务流程

```
浏览处方药 → 标记 is_rx=1，详情页显示"处方药，需凭方购买"
   ↓
点击购买 → 拦截，进入处方获取流程
   ↓
┌─ 已有处方：上传处方照片 → 药师审核
└─ 没有处方：跳转合作互联网医院在线问诊 → 医师开方 → 处方回传
   ↓
药师审核通过 → 处方状态置为"有效"并绑定用户
   ↓
用户下单 → 结算时强制校验：订单内每个处方药都必须有有效处方
   ↓
支付 → 发货
   ↓
处方归档留痕（≥2 年）
```

## 五、风险与提醒

| 风险 | 影响 | 应对 |
|------|------|------|
| **备案拖延** | 全部微信能力卡死 | 今天就去提交；期间用 IP + Mock 开发 |
| **小程序药品类目审核不过** | 无法上架 | 提前准备好《药品经营许可证》等材料 |
| **处方药合规** | 违规可被处罚甚至吊证 | 严格"先方后药" + 药师审核 + 处方留存 ≥2 年，**不可为体验妥协** |
| **即时配送成本** | 每单 5–15 元，可能吃掉毛利 | 询价接口要在结算页明示运费，设起送价 |
| **运力商回调丢失** | 订单卡在"配送中" | 必须有回调日志表 + 定时补偿查询 |

### 关于处方药的一条硬提醒

> **不要为了"流程顺畅"而让处方药可以先付款后补方。**
> 这是监管红线，一旦被查，处罚力度远大于省下的转化率。
> 正确做法是：处方药在**加入购物车时就拦截**，引导先获取处方。
