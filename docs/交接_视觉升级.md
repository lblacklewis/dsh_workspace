### 🔥 三个关键设计决定（别改坏）

**1. 审方人资格校验用「自激活」，不引入配置开关**

《处方药网络零售合规指南》第二十二条：处方审核**必须由本企业执业药师开展**。
但后台 `/api/admin/prescription/audit` 传进来的是**后台管理员 id**，不是药师 id ——
不校验的话任何管理员都能审方，直接违规。

策略：
- `eb_pharmacist` 里**存在**可审方药师 → **强制校验**，非药师 id 直接拒绝
- **一条都没有** → 放行 + 打 ERROR 点名（不把演示环境打死）

好处：**上线前录入药师后自动开始强制**，不依赖谁记得打开开关。
已实测：录入王药师后，admin(id=6) 审方被拦住。

**2. 「跳过未实现平台」的防护是从配送模块复制过来的**

配送模块踩过：5 个运力商 `is_enable` 全是 1，但代码只实现 mock，
全靠 mock 的 sort=0 最小才没出事；停掉 mock 就会取到未实现的平台 → 全部失败。
处方这边**沿用同一套**：按 sort 遍历、跳过代码未实现的、逐个 ERROR 点名。

**3. 签名字段顺序做成可传参**

文档**只写明** 3.1 的拼接顺序（`secretKey + bizID + clientID + timestamp`），
但 3.5/3.6/3.7 字段更多，文档没说要不要把它们也拼进签名。
所以 `signWithOrder(secretKey, params, order)` 把顺序做成参数，
拿到对方确认后只改配置，不动调用方。

### ⚠️ 要告诉对方的一个结论：文档给的签名样例算不通

用文档第 14 页的 `sign` 反推（脚本 `docs/verify-taozhi-sign.js`），
**6 种常见拼法全不匹配**；第 20 页的 `sign` 试 5 种也不匹配。
说明文档里那个 `secretKey` 只是格式示例，与示例 JSON 的 clientID 不是同一套。

**所以签名无法离线自验**，必须等正式凭证后在沙箱验证。
另：文档「签名Demo」章节贴了真实可用的 `secretKey` —— **建议让对方换发**。

### PDF 读取的坑（省得重踩）

这份 PDF 是 Word 导出，大量 **Type3 单字字体**（一个字体对象只映射一个字符），
且同一字体下**码的字面长度混用**（`<B5>` 是 1 字节码、`<0F53>` 是 2 字节码，
但 CMap 都声明 `<00> <FF>`）。

我手写零依赖提取器**踩了三个坑**（后代字体取错 CMap / 合并所有 CMap 互相覆盖 /
按 codespacerange 固定码宽切分），最后**只抽出 311 个中文字符（约 1%）**；
改用 **pdfjs-dist** 一次拿到 3390 个，完整可读。

**结论：不要手写 PDF 文本提取器。** 用 pdfjs（装在临时目录，不进项目依赖）。
另外 **Edge 的 `--screenshot` 无法渲染 PDF**（截出来是白页），要用 `docs/pdf-render.js`（走 CDP）。

## 〇之负二、第 22 轮：同城配送「配置与实现不一致」隐患修复

### 背景：用户问「发货流程是自动的吗」

查证结论：**是自动的**。`OrderPayServiceImpl.autoDispatchDelivery()` 在支付成功回调里触发：

1. `shippingType == 3`（1 快递 / 2 到店自提 / 3 同城即时配送）才走
2. 查运力商是否启用，没启用记警告
3. **幂等**：已有配送单直接跳过（防重复支付回调重复发单）
4. 调 `dispatch()` 发单
5. 整个 `autoDispatch()` 用 try-catch 包住 —— **发单失败绝不让已付款订单回滚**
   （否则用户付了钱却看到"支付失败"），失败只记日志，由后台人工补单

前后台都接好了：结算页有「快递发货 / 同城配送」切换 + 实时询价；
后台有 `配送管理 → 同城配送` 菜单（menu 553/554/555）。

### 发现的隐患（本轮修复的核心）

`eb_delivery_provider` 里 5 个运力商的 `is_enable` **全是 1**，但代码里
**只实现了 `mock` 一个**。当时没出事纯属侥幸：

> `currentProvider()` 旧实现是「取 `is_enable=1` 里 `sort` 最小的那条」，
> 而 **mock 的 sort 恰好是 0（最小）**，所以永远命中它。
> 谁在后台把 mock 停掉（mock 自己的类注释里正好写着"生产环境务必把 mock 置 0"），
> 就会取到没实现的 `wx` → 返回 null → **所有同城订单发单全部失败**。

后台界面当时也帮不上忙：5 张卡片全显示「已启用」，那句
「未接入的运力商即使启用也无法真正发单」的提示**没说是哪一个**。

### 修了什么

| # | 改动 | 文件 |
|---|---|---|
| 1 | `currentProvider()` 改为**按 sort 遍历、跳过代码未实现的**，返回第一个「配置启用且已实现」的；被跳过的逐个记 ERROR 点名 | `DeliveryOrderServiceImpl.java` |
| 2 | 新增 `implementedProviderCodes()` / `auditProviderConfig()` | `DeliveryOrderService.java` + Impl |
| 3 | **启动自检**（`InitializingBean`）：打印「代码已实现 / 配置需清理 / 当前生效」，脏配置逐个 ERROR 点名。刻意不抛异常（配置脏不该让服务起不来） | `DeliveryOrderServiceImpl.java` |
| 4 | `/provider/list` 返回增加 `implemented` / `inUse` / `configBroken` 三个字段 | `DeliveryController.java` |
| 5 | `toggle` 启用前校验代码是否已实现，未实现直接拒绝并说明原因 | `DeliveryController.java` |
| 6 | 后台卡片：区分「已启用」/「未接入」/「已启用·未接入」（红），未接入的**启用按钮置灰**；有脏配置时顶部出**红色告警**并给出数量 | `ProviderCards.vue` |
| 7 | 数据修复：4 个未实现的 `is_enable=0`，并在 remark 里注明「代码未实现，勿启用」 | MySQL |

### 验证（都实测过）

- 启动日志：`运力商自检：代码已实现=[mock] 配置需清理=[wx, kuaidi100, meituan, fengniao] 当前生效=mock`
- 列表接口：mock=`implemented:true,inUse:true`，其余 `implemented:false`
- **启用未实现的 kuaidi100 → 被拒绝**：`运力商「快递100同城急送」(kuaidi100) 代码里还没有实现，启用后无法真正发单`

- **发单回归**：`test-auto-dispatch2.ps1` 建单支付 → 配送单 `provider=mock, status=1已发单, 收货人=张先生`；

### 二维码生成器是怎么验的（重要，别信感觉）

自己写的 QR 编码器**必须证明它是真二维码**，不能只看图「像」。做法：

1. **码字落位回读**：把 `encodeCodewords()` 产出的码字流按 Z 字形写进矩阵，再按同样规则读回来，
   逐位比对 —— v1/v2/v5/v9/v10、单块和多块全部一致。
2. **交错可逆**：`dataBlocks`/`ecBlocks` 交错成流再拆回来，和原始数据码字逐个相等。
3. **格式信息自洽**：用 BCH(15,5) 写出格式信息后再读回，EC 等级与掩码和写入时一致。
4. **导出 PNG 肉眼看结构**：定位图形、时序线、静区都规整。

> ⚠️ 排查过程中我**两次误判**「编码器坏了」，实际都是**测试脚本自己的 bug**：
> 一次是 `forEach` 的第三个参数（数组）遮蔽了外层循环变量，一次是解码时把 ECC 码字也当数据比。
> **教训：先证明「被测对象」和「测试工具」谁错**，别急着改被测对象。

## 六、必须记住的坑

1. **uni-app H5 的 `<image>` 编译成 `<uni-image><div style="background-image">`**
   —— CSS 宽高要打在内层 div 上，只写 `img`/`image` 不生效（已踩）

2. **PowerShell here-string 嵌在哈希表里会被解析器搞坏**
   —— 生成脚本用 **Node** 写，不要用 PowerShell（已踩，脚本直接没跑起来）

3. **`.ps1` 必须 UTF-8 with BOM**，否则中文乱码 + 解析错误
   👉 **本会话新踩**：`edit` / `write` 工具写回时会**把 BOM 去掉**，
   改完 `.ps1` 必须补 BOM，否则 PS 5.1 按 ANSI 读 → here-string 终止符识别不了 →
   报一堆莫名其妙的错（`Missing file specification after redirection operator` 等）。
   补法：
   ```powershell
   $p="D:\project\StorApp\crmeb_java\docs\apply-h5-override.ps1"
   $t=[System.IO.File]::ReadAllText($p,[System.Text.UTF8Encoding]::new($false))
   [System.IO.File]::WriteAllText($p,$t,[System.Text.UTF8Encoding]::new($true))
   ```
   检查：`[System.Management.Automation.Language.Parser]::ParseFile(...)` 错误数应为 0。

4. **banner viewBox 比例必须匹配显示区**（750×392 vs 362×189），否则 cover 裁切

5. **`fullPage` 截图会把 `position:fixed` 元素画在视口位置**
   —— 那是截图假象不是 bug

6. **本机 shell 出网被沙箱拦**，服务器可以。下载图片要在服务器上 `curl`

7. **替换静态资源走同名文件覆盖**，不动 `home_data`

8. 🆕 **Windows 命令行上限约 32K**
   —— 22KB 的 JS 转 base64 后一次 `ssh "echo $b64 | base64 -d > f"` 会报
   `The filename or extension is too long`。必须**逐个文件传**（见 `Send-RemoteFile`）。

9. 🆕 **`ssh` 前必须设 askpass**，否则会挂住（本会话实测挂到超时）
   ```powershell
   $env:SSH_ASKPASS_REQUIRE="force"; $env:DISPLAY="dummy"
   $env:SSH_ASKPASS="$env:TEMP\ssh_askpass.bat"   # 内容 "@echo off\necho <你的SSH密码>"
   ```

10. 🆕 **CDP 截图的 `clip.scale` 不会把 2 倍图降回 1**
    —— `Emulation.setDeviceMetricsOverride` 设了 `deviceScaleFactor: 2` 后，
    `Page.captureScreenshot` 出来仍是 780×1688。用 canvas 做像素探针时坐标要 **÷2**，
    否则会读错行、误判「白字看不见」（本会话踩了很久）。

11. 🆕 **别用缩略图判断颜色**
    —— 模型看到的预览图是缩放过的，缩放会把浅色 banner 的青色糊成一大片，
    误判成「首屏有一块脏青色」。判断颜色要用**像素探针**（`node cdp.js pix`）。

12. 🆕🔥 **后台不能用内联 `<style>` 注入（H5 那套在后台不适用）**
    —— 把 `<style id="storapp-admin">` 静态写进后台 `index.html` 后，
    服务端返回的 HTML 里明明有它，但页面跑起来 DOM 里**查不到这个节点**，
    连注入的 `<script>` 也一起消失。换成 `<link href="/static/storapp-admin.css">`
    **并且用 JS 在运行时自己建节点 + 守住它**（轮询 60×250ms + MutationObserver 兜底）才稳定。
    > 实测证据：在 `document_start` 装轮询，第一次检查（t+21~47ms，readyState=loading）
    > 时 `#storapp-admin` 就已经不存在了 —— 说明不是「后来被删」，是**解析出来的 DOM 里就没有**。

13. 🆕🔥 **cdp.js 复用浏览器 profile 会用缓存返回旧 HTML**
    —— 服务端文件明明改了、`curl` 也读到了新内容，但浏览器拿到的还是旧文档，
    于是出现「注入的东西在 DOM 里完全不存在」的假象。**排查这个坑花的时间最多。**
    两个必须做的防呆（已固化进 `cdp.js`）：
    1. 每次启动前 `fs.rmSync(UD, {recursive:true})` 清空 profile
    2. `Network.enable` + `Network.setCacheDisabled({cacheDisabled:true})`
    判断文档是否来自缓存：看 `performance.getEntriesByType('navigation')[0].transferSize`
    （0 或远小于文件大小 = 缓存命中）。**遇到「改了没生效」先怀疑这个，别怀疑代码。**

14. 🆕 **后台菜单图标写错名会静默变成空白**
    —— 菜单表 `icon` 列存的是 Element UI 图标名（`s-check`/`s-goods`…），
    写成库里不存在的名字（如 `clipboard`）**不会报错**，只是 `.el-icon-clipboard`
    这条 CSS 规则压根不存在 → `w=14 h=0`，视觉上一片空白。
    排查：`getBoundingClientRect().height === 0`。可用图标名可以这样列：
    ```bash
    F=$(ls /var/www/storapp/admin/static/css/*.css | head -1)
    grep -o 'el-icon-[a-z0-9-]*' "$F" | sort -u
    ```

15. 🆕 **PowerShell 里 `'a' + $x` 写在数组字面量里不会被求值**
    —— `@( 'F=' + $TARGET, 'next' )` 会把 `F=` 和 `$TARGET` 当成**两个元素**，
    于是远程脚本里 `F=` 是空的，后面报 `Permission denied` / `ambiguous redirect`。
    必须加括号：`@( ('F=' + $TARGET), 'next' )`。

16. 🆕🔥 **注释里写「反引号 + 美元 + 左括号」会被 PowerShell 立即执行**
    —— 我在 `deploy-admin.ps1` 的注释里写了一句「需要给 shell 用的 $ 要写成 \`$」，
    结果 PowerShell 把 `` `$(...) `` 当**子表达式**求值，把命令输出**按行拼进了远程脚本**，
    于是 `if [ -f $REMOTE/index.html ]` 被拆成三行、`set -e` 直接中断。
    **症状**：远程脚本报 `[: missing ']'` 或行号对不上。
    **排查**：`nl -ba /tmp/<远程脚本>` 看被拼坏成什么样。
    **纪律**：注释里永远别写这个组合；要举例就写中文描述。
    👉 顺带一条：**`deploy-admin.ps1` 换目录的三步（备份 / mv / mv）少任何一步都会让站点 500** —
    这轮因为脚本报错中断，站点 500 了两次。换目录前一定先确认 `test -f $STAGE/index.html` 通过。

17. 🆕 **注入层里不要出现「注入标记名」这个字面量**
    —— `apply-h5-override.ps1` 用 `s.count('data-sa-inject') == 1` 校验注入是否干净。
    我在 `h5-inject.js` 的注释里写了一次这个属性名（第一次是想说明、第二次是写警告），
    计数就变成 2、断言失败，而且报错只说「DOM 注入脚本数不对」，很难一眼看出是自己注释里写的。
    **现在靠纪律**：这个属性名只能出现在被拼接的那一处。

18. 🆕 **后台构建必须加 `--openssl-legacy-provider`**
    —— webpack 4（`@vue/cli-service` 4.0.0）+ Node 24，不加会因 OpenSSL 3 报
    `error:0308010C:digital envelope routines::unsupported`。
    ```powershell

    ```

19. 🆕 **主题页会覆盖 `app.scss` 的默认颜色**
    —— 后台主题是从 `localStorage` 的 `JavaPlatThemeConfigPrev` 恢复的，
    它会在 `created()` 时调用 `setings.vue` 的 `setLocalTheme()`，把 `--prev-color-primary`
    覆盖回主题表里的值（`columns` 分支下 theme-1 曾经是 `#0256FF` 蓝）。
    所以**改 `app.scss` 不够**，必须同时改 `theme.js` 的 `theme-2` 和 `setings.vue` 的

20. 🔥🔥 **H5 构建产物在 `app\dist\build\h5`，不是 `app\unpackage\dist\build\h5`**
    —— 这个工程是 HBuilderX 布局（源码在 `app/` 根，不在 `src/`），用
    `npm run build:h5` 构建时产物落在 **`app\dist\build\h5`**；
    `app\unpackage\dist\build\h5` 只是历史上留下的一份**陈旧副本**。
    **我为这个坑排查了非常久**：新加的页面明明进了 `pages.json`、也生成了 chunk，
    但我一直在 `unpackage` 那份旧目录里找，找不到就误判成「构建不编译新页面」，

21. 🔥 **H5(:8092) 的 nginx 原来没有 API 反代，所有接口都是 405**
    —— `:8092` 那个 server 只有 `location / { try_files ... }`，
    POST 请求全被静态服务拒成 **405 Not Allowed**，返回的是 HTML 错误页而不是 JSON。
    也就是说 **H5 端一个数据都拉不到**（首页商品、登录、订单全是空的）。
    已在 `:8092` 里补上 `/front-api/` 和 `/dev-api/` 两个反代，与 `:80` 保持一致。
    备份在 `/root/storapp-nginx-*.bak`。
    **验证**：`curl -X POST http://127.0.0.1:8092/front-api/api/front/login -d '{...}'` 应返回 JSON。

    构建约 44 秒。

23. **H5 登录接口与后台不同**

25. **运行时注入的元素要判断「当前是哪个页面」**
