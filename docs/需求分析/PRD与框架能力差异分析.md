# PRD 与 CRMEB 框架能力差异分析

> 基于《产品需求文档.md》(v0.9, 2026-09-14) 与 CRMEB Java 开源商城现有能力对照
> 生成时间：2026-09-14

---

## 一、核心结论

**PRD 要求的"合规购药闭环"中，处方药相关的全部核心能力 CRMEB 框架均不具备。**

CRMEB 是通用电商框架，没有医药行业属性。PRD 定义的 8 大模块 37 个页面中：

| 状态 | 模块数 | 页面数（估） | 占比 |
|------|--------|-------------|------|
| ✅ 框架已有，可直接配置 | 3 | ~12 | ~32% |
| ⚠️ 部分可用，需改造 | 2 | ~8 | ~22% |
| ❌ 完全缺失，需二次开发 | 3+ | ~17 | ~46% |

**最关键的缺口：处方药"先方后药"合规流程（PRD 最高约束）完全没有实现。**

## 二、模块级能力对照

| 模块 | PRD 要求 | CRMEB 支持 | 差距 |
|------|---------|-----------|------|
| **M1** 账号与基础 | 登录、个人中心、设置、地址、消息 | ⚠️ 部分 | 缺实名认证、健康数据授权管理 |
| **M2** 商城浏览 | 首页、分类、搜索、搜索结果 | ✅ 基本可用 | 缺 Rx/OTC 分区、Rx 结果标识 |
| **M3** 商品与药品 | OTC详情、Rx详情、说明书、品牌页 | ⚠️ 部分 | 缺 Rx 详情、说明书页、审方前信息屏蔽 |
| **M4** 交易 | 购物车、结算、支付、订单、售后 | ✅ 基本可用 | 缺处方校验、Rx 订单审方状态 |
| **M5** 处方与问诊 | 处方列表、详情、上传、问诊开方、审方 | ❌ 完全缺失 | 整个模块需从零开发 |
| **M6** 健康服务 | 药师咨询、健康档案、用药提醒、资讯 | ❌ 基本缺失 | 仅客服模块可复用 |
| **M7** 营销与会员 | 优惠券、积分、会员、活动 | ✅ 可用 | 需加 Rx/甲类OTC 促销排除规则 |
| **M8** 辅助与合规 | 资质公示、药品追溯、发票、客服、协议 | ⚠️ 部分 | 缺药品追溯、电子发票 |

## 四、合规红线与实现风险

| 红线要求 | 框架现状 | 风险等级 |
|---------|---------|---------|
| **先方后药** | ❌ 无处方概念 | 🔴 **极高** |
| **Rx/OTC 分区** | ❌ 无药品类型 | 🔴 高 |
| **审方前信息屏蔽** | ❌ 无权限门禁 | 🔴 高 |
| **实名制购 Rx 药** | ❌ 无实名认证 | 🔴 高 |
| **禁止 Rx 变相促销** | ⚠️ 营销模块无排除规则 | 🟡 中 |
| **资质公示** | ⚠️ 可用文章实现 | 🟢 低 |
| **风险警示语** | ❌ 需前端改造 | 🟡 中 |
| **健康数据加密** | ❌ 无健康数据概念 | 🟡 中 |

### ⚠️ 最重要的合规结论

**在"先方后药"流程开发完成前，不得上架处方药。**

如果直接上架 Rx 药品，属于违反《药品网络销售监督管理办法》的违规销售，面临：
- 行政处罚（责令停业、罚款）
- 平台下架
- 经营许可影响

**当前阶段的正确做法：只上架 OTC + 医疗器械 + 保健品。**
