## 2026-10-12 会话（二）：图片输入排查 + 编码备忘

### 问题：会话不能传图片，提示"模型不支持"

**根因**：该会话的模型选择是 `deepseek-v4-flash`，它是**纯文本模型**。

**实测结论**（api.scnet.cn 网关 + 215KB 真实截图，看 prompt_tokens 是否包含图片）：

| 模型 | prompt_tokens | 结果 |
|------|--------------|------|
| `deepseek-v4.1-flash` | 238 | ✅ 准确读出图内文字（红色 FAIL: / bucket-820->snap-63） |
| `deepseek-v4-flash` | 94 | ❌ 回"没看到图片" |
| `deepseek-v4-pro` | 15 | ❌ 回"看不到图片" |
| `glm-5.3` | — | ❌ 回"没有多模态输入能力" |

**结论**：网关侧**只有 `deepseek-v4.1-flash` 支持图片**；其余模型即使传 `image_url` 也会被丢弃。

**已做**：
- 模型名加防呆标注：`DeepSeek-V4.1-Flash 🖼 支持图片` / 其余标 `（纯文本）`
- `agent-default-model` 确认为 `deepseek-v4.1-flash`（新会话默认可传图）
- settings.yaml 顶部加**视觉模型备忘** + **编码模式备忘**

### 编码模式备忘（重要）

规则按**文件类型**区分：

| 文件 | 编码 | 原因 |
|------|------|------|
| `settings.yaml` / `package.json` / `*.yml` | **UTF-8 无 BOM** | 有 BOM 会导致解析失败、服务起不来 |
| `*.ps1` 脚本 | **UTF-8 with BOM** | PowerShell 5.1 才能正确显示中文 |

禁止用 PowerShell `Set-Content -Encoding UTF8` 写配置（会带 BOM），改用 `write` 工具或
`[System.IO.File]::WriteAllText($p, $t, [System.Text.UTF8Encoding]::new($false))`。

> 教训：2026-10-12 曾把 `profiles/web/package.json` 存成 UTF-8 with BOM，
> 导致 dsh web 解析 JSON 失败、重启起不来。

### 其他

- `todo-widget` 安装方式由 `file:`（副本）改为 `link:`（junction），改源码后**只需重启**、不必手动复制。
  > 注：切换时 pnpm 会因 `cloudflared` 目录被隧道进程占用而失败，可手动 `mklink /J` + 改 package.json 协议解决。

## 2026-10-13 会话：桌面版（DSH Desktop）配置适配

### 问题：家里桌面版崩溃，报 403 client 相关

**根因**：`setup.ps1` 把 **Web 版 settings.yaml 覆盖到共享位置** `~/.dsh/settings.yaml`，
其中的 **`remote-web-ui`** 配置（随 `@linxin666/dsh-web-all` 安装）在桌面版上闯祸：

1. `lanBind: true` → webserver 绑 `0.0.0.0`
2. `requirePairingForLan` 默认 true → 启用**配对门控**
3. 桌面版 Electron 渲染进程访问 `/api` 被判为未配对来源 → **HTTP 403**

### 关键事实：桌面版 vs Web 版

| 项目 | Web 版 | 桌面版 |
|------|--------|--------|
| profile 目录 | `~/.dsh/profiles/web/` | `~/.dsh/profiles/desktop/`（Electron 独占） |
| 插件安装 | `dsh plugin --profile web add <pkg>` | 应用内插件管理（CLI 禁止操作 desktop） |
| `settings.yaml` | **共享** `~/.dsh/settings.yaml` | **同一份** ⚠️ |

> Electron 侧约束（`apps/desktop/src/project-manager.ts`）：
> `DESKTOP_PROFILE_BUNDLES = ['@deepseek-ai/dsh-base', '@deepseek-ai/dsh-web-app']`，
> 且 `dsh` CLI 有 `rejectElectronProfile` 拒绝操作 desktop profile。

### 已做修复

1. **新增 `.dsh/settings.desktop.yaml`** —— 桌面版精简模板，剔除 `remote-web-ui`、
   `skin-*`、`pet`、`dsh-usage` 等 Web 专有配置，只保留模型路由/默认模型/预设。
2. **重写 `setup.ps1`** —— 加 `-Mode auto|web|desktop`：
   - `auto`（默认）：检测到 `~/.dsh/profiles/desktop` 就按桌面版处理
   - `desktop`：用精简 settings + **不复制 `profiles/`** + 检查 desktop profile 是否误装 web-all
   - 覆盖 settings 前自动备份
3. **README** 增加「桌面版特别注意」章节，说明 403 成因与避免方式。

```powershell
cd dsh_workspace

.\setup.ps1 -Mode desktop      # 覆盖掉含 remote-web-ui 的 settings
# 若桌面版应用内装过 @linxin666/dsh-web-all → 在应用内插件管理里卸载
# 重新配置 ~/.dsh/.credentials.yaml（两个 key）
```
