## 一、本轮发现并修掉的一个真问题

**症状**：H5 结算页把「微信支付」「支付宝」当成可用选项展示给用户，但点下去必然失败。

**根因**：CRMEB 判断"某支付方式可用"时**只看开关值，完全不校验凭证是否配了**：

```java
// OrderPayServiceImpl.getPayConfig() 原实现
String payWxOpen = systemConfigService.getValueByKey("pay_weixin_open");
response.setPayWechatOpen("1".equals(payWxOpen));   // 只看开关
```

而本项目初始化时：

| 配置项 | 值 | 问题 |
|---|---|---|
| `pay_weixin_open` | `'1'` | 开关是**开着**的 |
| `pay_weixin_appid` | `111` | 占位值 |
| `pay_weixin_mchid` | `111` | 占位值 |
| `pay_weixin_key` | `111` | 占位值 |
| `ali_pay_status` | `'1'` | 开关开着 |
| `ali_pay_appid` | `111111` | 占位值 |

于是前端返回 `{payWechatOpen: true, aliPayStatus: true}` —— 一个点了就报错的按钮。

**修复**：新增 `PaymentAvailability`（`crmeb-service/.../service/pay/`），统一判定
「**开关打开 且 凭证是真实值**」才算可用，收口到三处调用点：

- `OrderPayServiceImpl.getPayConfig()` —— 前端读的支付配置
- `OrderServiceImpl.loadPreOrder()` / `getPayConfig()` —— 结算页读的配置
- `OrderUtils.checkPayType()` —— 创建支付时的后端拦截

这样前端隐藏 + 后端拦截两边一致，不会出现"前端没这个选项、后端却允许"的缝隙。

**效果**（实测）：

```
修复前: {yuePayStatus:true,  payWechatOpen:true,  aliPayStatus:true}   ← 微信/支付宝是假的
修复后: {yuePayStatus:true,  payWechatOpen:false, aliPayStatus:false}  ← 只剩真实可用的余额
反证:   填入格式合法的凭证后 payWechatOpen 立即变 true
```

**占位值判定规则**（保守，宁可漏判也不误判真实凭证）：空值 / 全同字符（`111`）/ 长度 < 8 /
含 `test`、`xxxx`、`1111old` 等词 → 判为未配置。

启动时会打一行日志，配置问题一眼可见：

```
[PaymentAvailability] 启动检查: 微信支付=不可用(开关未开或凭证未配置) 支付宝=不可用(...) 余额=可用
                      ｜ 开关原始值: wx_open=['1'] ali_status=['1'] yue_status=['1']
```

## 二、⚠️ CRMEB 的一个坑：开关值是带引号存的

排查过程中踩到：`eb_system_config.value` 里的开关**连引号一起存**。

```sql
-- 实测
name              value   LENGTH  HEX(value)
yue_pay_status    '1'     3       273127      -- 273127 就是 '1' 三个字符
```

官方常量本身就带引号：

```java
public static final String CONFIG_FORM_SWITCH_OPEN  = "'1'";
public static final String CONFIG_FORM_SWITCH_CLOSE = "'0'";
```

所以**不要写** `"1".equals(value)`，要么用官方常量，要么两种写法都认。
这个坑的表现是"配置明明是开的却判定为关"，且不报任何错，极难排查。

## 三、需要准备的凭证清单

### 微信支付（小程序 / 公众号 JSAPI）

| 配置项 | 说明 | 从哪来 |
|---|---|---|
| `pay_weixin_appid` | 公众号 AppID（`wx` 开头 18 位） | 微信公众平台 → 设置与开发 → 基本配置 |
| `pay_weixin_appsecret` | 公众号 AppSecret | 同上 |
| `pay_weixin_mchid` | 商户号（10 位） | 微信商户平台 |
| `pay_weixin_key` | APIv3 密钥（32 位） | 商户平台 → 账户中心 → API 安全 |
| `pay_weixin_certificate_path` | 商户 API 证书 apiclient_cert.pem | 商户平台 → API 安全 → API 证书 |
| `pay_mini_app_client_p12` | 小程序支付证书 | 同上 |

> 小程序场景还需要 `pay_routine_appid` / `pay_routine_appsecret` / `pay_routine_mchid` / `pay_routine_key`。

### 前置条件（按依赖顺序）

1. **域名 + ICP 备案** ← 目前唯一硬阻塞，7–20 工作日
2. **HTTPS**（微信支付强制要求，回调必须 https）← 域名备案后才能配
3. 微信公众平台配置**服务器域名白名单**：把 `https://<域名>` 加进 request 合法域名
4. 商户平台配置**支付授权目录**
5. 申请**微信物流助手-即时配送**能力（第 ① 条链路要用）

- 微信支付回调：`WebSecurityConfig.java:147` 已有 `.antMatchers("/api/admin/payment/callback/**").anonymous()`

> 注意：支付回调走的是 **admin 服务**（20600），配送/处方回调走 **front 服务**（20610）。

## 五、HTTPS 配置（域名备案下来后执行）

```nginx
# /etc/nginx/conf.d/storapp.conf
server {
    listen 80;
    server_name your-domain.com;
    # 备案下来后强制跳 https；保留一个 http 入口用于证书续期
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 后台（含支付回调）
    location /dev-api/ {
        proxy_pass http://127.0.0.1:20600/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 100m;
    }

    # 前台 API
    location /front-api/ {
        proxy_pass http://127.0.0.1:20610/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # H5
    location / {
        root /var/www/storapp/h5;
        try_files $uri $uri/ /index.html;
    }

    # 图片
    location /crmebimage/ { alias /opt/storapp/crmeb/crmebimage/; }
}
```

证书用 certbot 自动续期：

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d your-domain.com
systemctl list-timers | grep certbot   # 确认自动续期定时器已装
```

> ⚠️ 部署 H5 时注意：`open_file_cache` 会缓存最多 5 秒，改完必须 `systemctl reload nginx`，
> 否则会拿到旧文件（详见《云端部署记录》）。

## 六、凭证到位后的启用步骤

1. 后台「设置 → 支付配置」填入微信支付凭证（或直接改 `eb_system_config`）
2. 确认 `pay_weixin_open` = `'1'`（**注意带引号**）
3. 重启服务，看启动日志：
   ```
   [PaymentAvailability] 启动检查: 微信支付=可用 ... ｜ 开关原始值: wx_open=['1'] ...
   ```
   显示"可用"才算配置成功
4. 前端接口自检：
   ```bash
   curl -H "Authori-zation: <token>" https://<域名>/front-api/api/front/pay/get/config
   # 期望 payWechatOpen: true
   ```
5. 商户平台把回调地址填成第四节里的 url
6. 下一笔 1 分钱真实订单验证闭环
